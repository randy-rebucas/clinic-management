## 1. Audit the page (functional first)

Read the page's `page.tsx` and its client component(s) and the API route(s) they call. Write down defects before styling. The pattern so far: **every page had real bugs** hiding under the old look. Typical finds:
- stats computed from the current page instead of the whole dataset;
- loading and empty states shown at once; skeleton flash on every refetch;
- controls that do nothing (a "global"/"all clinics" toggle the API ignores, an "Apply" that only `console.log`s);
- literal `&apos;` inside JS strings (renders verbatim);
- missing error/retry states, race conditions between requests;
- misleading labels (counts that exclude statuses, "My X" showing clinic-wide data).

Fix the cause at the narrowest level, including API routes when the data is wrong or missing. Prefer aggregation endpoints over loading all records. Respect RBAC (`requirePermission` / `hasPermission`) and tenant scoping (`tenantFilter`, `patientTenantFilter`) on anything new.

## 2. Design the page

- Follow the **roster pattern** for list pages and the **dashboard panels** for detail/overview pages. Title (extrabold, tight) sits on the gray-50 ground — no header card, no icon chip.
- Add a chart only when it answers a question the user of that page actually has (e.g. appointments: day/week load, status mix; invoices: aging buckets, collected vs billed; inventory: stock vs reorder level, expiry horizon; queue: wait time). Make a summary chart double as a filter when it maps to an existing filter.
- Colour: run `node <dataviz>/scripts/validate_palette.js "<hex,...>" --mode light --pairs all` (and `--mode dark`) for any new categorical set. Reuse validated values first: Chart Teal `#0E9594`, Chart Blue `#2563EB`, Chart Ochre `#B45309`; states upcoming `#2563EB`, seen `#0E9594`, pending `#D97706`, no-show `#BE123C`, cancelled = gray outline + strike. Purple and slate already failed (purple≈blue under deuteranopia; slate≈teal).
- Contrast: small text never on bright `brand-teal`. Text-bearing fills use `bg-brand-teal-dark` hover `bg-brand-teal-deep`; text on `brand-teal-light` uses `text-brand-teal-deep`. Red only for destructive or needs-attention.
- Every chart: tooltip on pointer and keyboard, legend for ≥2 series, `TableTwin` ("View as table"), one y-axis.
- Motion: reuse `motion-*` classes. One authored moment per page at most, tied to meaning (the Clinic Day sweep is the model); otherwise rows ease in (capped stagger), panels/chips fade, trays rise. Never lift/scale on hover (Tint-Not-Lift).
- Copy: plain, specific, the product's own words. List every user-visible wording change in the final report.

## Traps already hit (don't repeat)

- **Never trim or collapse whitespace in bulk string rewrites.** A migration once turned `.split(' ')` into `.split('')` and `'Error: '` into `'Error:'` across 40 files. Mechanical class rewrites touch class tokens only.
- **Bulk scripts must not include hand-edited files**, or they silently revert them (this reset `SidebarContext.tsx` and `app/(app)/layout.tsx` once).
- **CRLF files**: some files (e.g. `components/types/PatientTypes.ts`) use CRLF; exact-match patch scripts fail. Use the Edit tool.
- **Route files** may only export handlers; shared constants go in `lib/` (see `lib/patient-age-bands.ts`).
- **Lint `set-state-in-effect`**: don't call `setLoading(true)` synchronously in an effect. Derive loading from a request key vs a settled key (see `useDashboardData`, `PatientsPageClient`).
- **Tailwind classes must be static strings** (use full maps, not `bg-${color}-500`).
- Login (`components/LoginForm.tsx`, `app/(auth)`), `BrandLogo`, and public-only screens are brand-bound per `PRODUCT.md`: leave them.
